# TermsGuard

Review clause classifications in Terms of Service and Privacy Policies.

TermsGuard extracts clauses from a policy document and classifies each clause as Safe, Neutral, or
Risky using a trained machine-learning model. It is an educational screening tool, not legal advice,
and a missing Risky prediction does not establish that a document is safe.

## Start

### Python environment

From the repository root:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### Backend

```powershell
cd backend
python -m uvicorn app.main:app --reload --port 8000
```

Backend runs at `http://127.0.0.1:8000`. Model readiness:
`http://127.0.0.1:8000/api/v1/health`

### Frontend

```powershell
cd frontend
npm ci
npm run dev
```

Frontend runs at `http://127.0.0.1:3000`.
It calls the FastAPI service at `http://localhost:8000` by default. Set
`VITE_API_URL` in `frontend/.env.local` when the backend is hosted elsewhere.

## Fresh clone reproduction

A fresh clone does **not** run immediately. Raw data, model weights, and the
Python environment are local-only and excluded from Git. The sequence below
shows how to reproduce everything from source:

### 1. Obtain data (must be provided separately)

Raw datasets are Git-ignored (`data/raw/*`) and are not included in the
repository. Place the prepared benchmark data under `data/` so that
`src.splitting.load_development_bundle` can find it:

```
data/
  raw/                  cases.csv, points.csv, documents.csv, services.csv, topics.csv
  processed/
    clauses_benchmark_v1.csv
  splits/
    split_manifest_v1.csv
    split_manifest_v1.json
```

The dataset hash is `cee557cc927d754cf17675154ed5e1e32eee2fdb9af6700c526e62cd66969f8c`.

### 2. Build the Python environment

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### 3. Train all eight methods

```powershell
python scripts\run_comparison.py --protocol both
```

This trains and tunes all eight classifiers on the fixed group-respecting
development splits, with genuine cross-validation, and writes results to
`results/comparison/{primary,clause}/`. Model artifacts are saved under
`models/{method}/artifacts/{protocol}/`.

### 4. Package the production model (optional)

```powershell
python scripts\build_frozen_model_package.py
```

This rebuilds `models/releases/linear-svc-primary-v2/` from the training data
using the frozen candidate recipe (LinearSVC, C=1, class_weight=balanced).
**Warning:** this overwrites the frozen release artifact. The frozen release is
preserved as committed; regenerating it produces a newly trained package whose
weights may differ due to environment/version differences. Do not run this unless
you intend to replace the frozen release.

### 5. Start the application

Backend:
```powershell
cd backend
python -m uvicorn app.main:app --reload --port 8000
```

Frontend (separate terminal):
```powershell
cd frontend
npm ci
npm run dev
```

### 6. Verify

```powershell
python -m pytest backend/app/tests -q          # backend tests (45)
python scripts\check_parity.py                  # offline vs API prediction parity
python scripts\verify_split_manifest.py         # data/split integrity
```

### Frozen release vs newly trained package

The committed `models/releases/linear-svc-primary-v2/` is the frozen production
release and is **not** regenerated by normal training. A newly trained package
from `scripts/build_frozen_model_package.py` may produce different weights due
to environment/scikit-learn version differences. The frozen release is the one
served by the backend and verified by the parity check.

```powershell
python scripts\run_comparison.py --protocol both
```

Writes per-protocol results to `results/comparison/{primary,clause}/`:
- `comparison.csv` — machine-readable metrics for all eight methods
- `comparison.md` — readable comparison table
- `{model}_confusion_matrix.csv` — per-model confusion matrices
- `run_metadata.json` — run identity, data/split identity, environment

Each model folder under `models/` contains `README.md`, `config.json`, `code.ipynb`,
`results/{primary,clause}/`, and `artifacts/` (fitted development pipeline).

## Model scope

Compared fairly on the same development data and splits:

1. Multinomial Naive Bayes
2. Logistic Regression
3. Linear SVM (production model)
4. RBF SVM
5. Decision Tree
6. Random Forest
7. K-Nearest Neighbours
8. Gradient Boosting (HistGradientBoosting)

Not in scope: Complement Naive Bayes, voting/stacking ensembles, sentence embeddings,
K-means clustering, PCA on embeddings, calibration/abstention experiments.
