## Locked-test boundary incident and containment

On 3 November 2026, the embedding smoke/full runs and the first primary classical-tuning attempt called the pre-existing `load_split_bundle`. That function returns a dataframe containing train, validation, and excluded test rows; therefore the complete dataset text and labels were materialized in memory before the experiment scripts filtered to development partitions. The smoke run cached 128 development embeddings. The interrupted full embedding run reached about 6,400 of 18,635 development rows and wrote no cache. The interrupted tuning run emitted fold progress but wrote no result files. These scripts computed and printed only development-fold metrics; no test metric or test-label summary was produced, viewed, or used for selection.

The incident is recorded as a test-boundary breach: the split must no longer be called untouched. No reselection or test-driven tuning followed. The shared loader was corrected for future development work by adding `load_development_bundle`, which verifies the source checksum, scans CSV record boundaries while retaining only point IDs, writes only train/validation records to a temporary file, and lets pandas parse only that file. The loader returned only the expected development partition row counts under both protocols. All subsequent development experiments use this loader. The candidate was later frozen in writing and each locked protocol was scored once; those are the first scored test metrics after this incident. The incident is disclosed in `docs/LOCKED_TEST_EVALUATION_v1.md`; no test-driven tuning followed.
